# Dashboard Sprint — Unique Visual Identity & Interaction Design Brief

## 0. CORE DIRECTIVE

Build a dashboard that feels like a **new visual product**, not an AI-generated SaaS dashboard.

This is an **AI-enabled smart nutrient balancing system for controlled hydroponics**.

The interface must visually communicate:

* Living plants
* Water
* Nutrients
* Sensors
* Biological balance
* Prediction
* Environmental change
* Early stress detection
* A physical system that is continuously alive

The UI should feel like a **premium digital instrument for a living ecosystem**.

It must NOT look like:

* ChatGPT
* Gemini
* Claude
* Generic AI dashboards
* Generic SaaS admin panels
* Cyberpunk interfaces
* Cryptocurrency dashboards
* Neon tech products
* Glassmorphism templates
* Generic "green sustainability" websites
* Generic futuristic farming websites
* A dashboard generated from a UI template

### Design philosophy

> **Do not decorate a dashboard with futuristic effects.
> Make the behavior of the living hydroponic system itself become the visual identity.**

The interface should feel calm, strange, intelligent, organic and engineered at the same time.

---

# 1. VISUAL CONCEPT

## Concept Name

### "LIVING INSTRUMENT"

The dashboard is treated as an instrument that is monitoring a living environment.

Think:

**scientific instrument + botanical laboratory + editorial art direction + experimental motion design**

NOT:

**AI + glowing cards + gradients + green leaves**

The interface should feel like something that could belong to a completely new hardware/software company.

# 7. TYPOGRAPHY

Typography should be a major part of the identity.

Use a modern grotesk / neo-grotesk style for the interface.

Pair it with a restrained mono font for:

* sensor IDs
* timestamps
* measurements
* system states
* model metadata
* inference latency
* uncertainty values

Example hierarchy:

```text
SYSTEM OVERVIEW

05
ACTIVE SENSORS

pH
5.82

TDS
812 ppm

LAST SAMPLE
00:10:32
```

Large numbers should feel editorial.

Do not make everything tiny.

Do not make every label uppercase.

Use typography to create hierarchy.

# 9. SPLASH SCREEN

The first screen should establish the identity immediately.

Do NOT make a normal:

```text
Logo
Loading...
Progress bar
```

Instead:

### THE SYSTEM WAKES UP

Start with an almost empty dark screen.

A very small point appears.

Then:

```text
WATER
```

appears.

A thin organic line grows from it.

Then:

```text
NUTRIENTS
```

appears.

Another line forms.

Then:

```text
ENVIRONMENT
```

Then:

```text
PREDICTION
```

These elements gradually connect.

The interface visually constructs the system.

Finally the brand mark appears.

The entire animation should feel like:

> **a living system booting up**

Not a loading animation.

---

# 10. SPLASH ANIMATION

Use:

* liquid deformation
* slow organic movement
* thin vector paths
* subtle particles
* fluid curves
* microscopic movement
* asymmetric timing

Avoid:

* spinning loaders
* circular progress rings
* excessive particles
* fireworks
* glowing AI particles
* generic "AI loading" animations

Animation duration:

```text
~2.5–4 seconds
```

It should be beautiful enough to feel intentional but fast enough not to annoy users.

---

# 11. CURSOR AS PART OF THE BRAND

The cursor must NOT be a normal browser cursor.

Create a custom cursor.

The cursor should behave like a **small moving botanical/chemical field**.

### Default

Small irregular copper point.

Not a circle.

Not a glowing dot.

Not a futuristic crosshair.

When moving:

A very subtle organic trail follows the cursor.

The trail should deform and disappear naturally.

---

# 12. PLANT-CURSOR INTERACTION

This is one of the signature interactions.

There should be a small living plant visualization somewhere in the main interface.

When the cursor approaches it:

### The plant notices the cursor

The plant should:

* slightly bend toward the cursor
* move leaves subtly
* react with delayed motion
* create tiny deformation waves
* slightly change its posture

The reaction must feel physical.

Not:

```text
hover → scale(1.1)
```

Instead:

```text
cursor movement
      ↓
distance calculation
      ↓
plant responds
      ↓
spring physics
      ↓
leaf deformation
```

The plant should feel alive.

---

# 13. CURSOR INTERACTIONS

Use magnetic interaction sparingly.

Examples:

### Navigation

The active navigation item slightly pulls toward the cursor.

### Buttons

Buttons have a subtle physical displacement.

### Data points

When the cursor approaches a chart point:

The point reacts before the cursor actually touches it.

### Plant

Leaves move toward the cursor.

### Forecast

The forecast line subtly reveals more detail around the cursor.

### Stress event

Hovering a stress event causes a localized ripple through the timeline.

# 17. TDS SHOULD BE THE VISUAL STAR

TDS is one of the most important difficult variables in the research.

Give it a unique visualization.

Instead of a normal line chart:

Create a **density field**.

Imagine the TDS value as a vertical concentration column.

As concentration increases:

```text
low density
     ↓
medium density
     ↓
high density
```

The visual density changes smoothly.

When nutrient dosing occurs:

Create a short physical-looking disturbance.

This makes the interface visually connected to the actual engineering problem.

# 20. STRESS DETECTION

Stress detection must feel like an important system event.

When stress is detected:

Do NOT use:

```text
RED ALERT CARD!!!
```

Instead:

The interface should subtly change.

Examples:

* typography shifts
* a thin copper/oxide line travels through the interface
* chart timeline highlights the event
* plant visualization changes posture
* sensor visualization becomes more active
* system state changes

Example:

```text
SYSTEM STATE

NUTRIENT
STRESS DETECTED

TDS
↑ 1095 ppm

CONFIDENCE
0.91
```

The whole interface should communicate the event.

# 29. MOTION PRINCIPLES

Every animation must follow these principles:

### 1. Organic

Nothing should move perfectly linearly.

### 2. Physical

Movement should have:

* inertia
* acceleration
* deceleration
* spring behavior

### 3. Delayed reaction

Plants and system elements should react slightly after the cursor.

### 4. Calm

No constant pulsing.

No aggressive spinning.

No endless motion.

### 5. Meaningful

Motion should communicate:

* change
* interaction
* prediction
* stress
* flow
* system state

If an animation does not communicate anything, remove it.

# 32. ACCESSIBILITY

The visual identity must remain usable.

Ensure:

* readable contrast
* motion reduction support
* keyboard navigation
* clear state indicators
* color is never the only indicator

* important alerts have textual descriptions

```css

```

Do not try to make the dashboard look futuristic by adding futuristic decorations.

### Make the interface behave like a living hydroponic system

# 37. FINAL DESIGN TEST

Before considering the dashboard complete, ask:

### If the logo and text were removed, would this interface still be recognizable?

If NO → redesign it.

### Does it look like an AI dashboard?

If YES → redesign it.

### Does it look like a generic green sustainability product?

If YES → redesign it.

### Does it look like a template?

If YES → redesign it.

### Does the motion communicate the physical system?

If NO → redesign it.

### Does the color palette feel proprietary?

If NO → redesign it.

### Does the cursor feel like part of the product?

If NO → redesign it.

### Does the plant actually react to the user?

If NO → redesign it.

### Does the dashboard feel like an instrument for a living system?

If YES → we are going in the right direction.
